# Releasing

## How it works

1. Push a version tag:

   ```sh
   git tag v0.2.0
   git push origin v0.2.0
   ```

2. [`.github/workflows/release.yml`](../.github/workflows/release.yml) then runs on a macOS runner:
   - runs `swift test`
   - builds a universal (Apple Silicon + Intel) `TomTomSync-v0.2.0.zip` with `scripts/build-app.sh --zip`
   - publishes it as a GitHub release with generated release notes
   - writes `Casks/tomtomsync.rb` with the new version and SHA-256 to
     [dzgnnl/homebrew-tap](https://github.com/dzgnnl/homebrew-tap), generated by
     `scripts/update-cask.sh` from `packaging/homebrew/tomtomsync.rb.in`

3. Users get the new version with `brew upgrade`.

[`ci.yml`](../.github/workflows/ci.yml) builds and tests every push to `main` and every pull request.

## One-time setup

1. Create the public GitHub repository `dzgnnl/TomTomSync` and push `main`.
2. Create the public repository `dzgnnl/homebrew-tap` with a README. Homebrew
   finds a tap by this `homebrew-` naming convention, so users type `dzgnnl/tap/tomtomsync`.
3. Create a fine-grained personal access token (GitHub → Settings → Developer
   settings → Fine-grained tokens):
   - Repository access: only `dzgnnl/homebrew-tap`
   - Permissions: **Contents: Read and write**
4. Add it to the TomTomSync repository as an Actions secret named `TAP_TOKEN`
   (Settings → Secrets and variables → Actions).
5. Turn on private vulnerability reporting (Settings → Security), which
   [SECURITY.md](../SECURITY.md) refers to.

## Signing

Releases are currently signed ad hoc: they have a code signature, but no Apple
Developer ID. Effects:

- **Homebrew:** the cask removes the quarantine flag after installing, so the
  app opens without a Gatekeeper warning. Installing from the tap is the user's
  trust decision. Homebrew allows this in personal taps but not in the official
  `homebrew/cask`, so TomTomSync cannot go there unsigned.
- **Downloading the ZIP from Releases:** Gatekeeper blocks the first launch of
  each version, and the user clicks **Open Anyway** in Privacy & Security.
- **Self-built:** no warning, because locally built apps are not quarantined.

Moving to Developer ID signing is an open item; see [ROADMAP.md](ROADMAP.md).
`scripts/build-app.sh` already supports it through `SIGN_IDENTITY` and `NOTARY_PROFILE`:

```sh
xcrun notarytool store-credentials tomtomsync   # once; Apple ID + app-specific password
SIGN_IDENTITY="Developer ID Application: Name (TEAMID)" NOTARY_PROFILE=tomtomsync \
  scripts/build-app.sh --zip
```

In CI, the certificate (.p12 + password) and the notarytool credentials would
become Actions secrets, imported into a temporary keychain before the build.
